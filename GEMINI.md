# Project Memory & Agent Guidelines (`GEMINI.md`)

## 1. Project Overview

**PassthroughHandsFreeController** is a Mixed Reality (Passthrough) Unity application running on Windows (targeting **Meta Quest** headsets) that enables **hands-free navigation of a robotic wheelchair** via head-gaze and dwell-time interactions. It communicates over HTTP with any robotic wheelchair server implementing the **RestThru** REST protocol.

- **Execution Environment**: Unity Editor `6000.6.7f1` running natively on Windows (using a dedicated NVIDIA GeForce GTX 1650 Ti GPU).
- **Core Packages**:
  - `com.meta.xr.sdk.all`: `207.0.1`
  - `com.unity.xr.meta-openxr`: `2.6.1`
  - `com.unity.render-pipelines.universal`: `17.6.0`
- **Main Scene**: `Assets/Scenes/PassthroughHandsFreeController/PassthroughHandsFreeController.unity`

## 2. Application Architecture

All core scripts reside in `Assets/Scenes/PassthroughHandsFreeController/Scripts/`:

### State Machine (`AplicationController/`)
- **`ApplicationController.cs`**: Application entry point. Initializes `StateContext`, starts directly in `MainMenuState` (using the saved `PlayerPrefs` RestThru IP/Port or falling back to the default `192.168.0.2:8080`), and runs `VibrateRoutine()` (sending a `0.001f` vibration pulse to `RTouch` every 2 seconds) so the Quest OS does not put the mounted Touch controllers to sleep when untouched by the user.
- **States (`AplicationController/States/`)**:
  - `MainMenuState.cs`: Displays `MainMenuUI` with a live server reachability badge (`Online`/`Offline`) and *Move Wheelchair* (`SelectingMovementTargetState`), *Rotate in Place* (`RotatingState`), and *RestThru Server* (`ServerConfigState`) buttons.
  - `ServerConfigState.cs`: Displays `ServerConfigUI` at the same spatial anchor as `MainMenuUI` (pre-filled with the saved `PlayerPrefs` IP/Port or `192.168.0.2:8080`), allowing configuration via head-gaze dwell, controller button `A`, keyboard, or Editor `OnGUI` overlay, and returns to `MainMenuState` when confirmed (*Connect*) or cancelled (*Back*).
  - `SelectingMovementTargetState.cs`: Activates `CameraGazeCursor` to let the user pick a target point on the floor mesh (`FLOOR_EffectMesh`).
  - `MovingState.cs`: Calls `MovementSequenceController.PerformLinearDisplacement(target)` -> `RestThruAPI.ScheduleGotoPoint2d(...)`. Transitions to `ConfirmingRotationState` upon completion.
  - `ConfirmingRotationState.cs`: Displays `ConfirmRotationUI` (`TwoButtonsCameraGazeControlledCanvas`) prompting the user to either adjust the wheelchair's heading (`RotatingState`) or return to target selection (`SelectingMovementTargetState`).
  - `RotatingState.cs`: Calls `MovementSequenceController.FollowTargetAligment(OVRUtils.CenterEyeAnchor)` -> `RestThruAPI.ScheduleAlignHeading2D(...)`. Transitions to `SelectingMovementTargetState` when finished.

### Hands-Free Head-Gaze & Spatial UI (`CameraGazeCursor` & `UI/`)
- **`HandedInputSelector.cs`**: Sets `OVRInputModule.rayTransform = m_cameraRig.centerEyeAnchor` every frame so `OVRRaycaster` UI canvases are driven by head gaze (without being hijacked by the stationary Touch controllers mounted on the wheelchair armrests).
- **`ToggleGazeInteractor.cs`**: Drives procedural head-gaze dwell interactions (`timeToToggle` seconds, or immediate with button `A`) for both `Toggle` and `Button` components without requiring `AnimatorController` assets. Interpolates scale, background color (`GazeButtonStyle` presets: `Primary`, `Secondary`, `Danger`, `Keypad`, `SubtleIcon`), and a bottom horizontal progress bar (`GazeProgressBar`), and plays spatial audio feedback.
- **`CameraGazeCursor.cs` / `CursorController.cs` / `HitpointIndicator.cs`**:
  - Casts a `Physics.Raycast` from `CenterEyeAnchor` and only activates the cursor when hitting `"FLOOR_EffectMesh"` (generated by MRUK `EffectMesh`).
  - When the gaze hit point stays within `distanceThreshold`, `HitpointIndicator` scales up to `maxScale` over `hitpointTimeToTrigger` seconds (or skips immediately when button `A` is pressed), opening `SelecTargetUI` (`SelectTargetUI.cs` — note the class name is `SelecTargetUI` without the first 't').
- **`CameraGazeControlledCanvas.cs` & `LineOfSightPositioner.cs`**:
  - Base class for gaze-controlled canvases (`ServerConfigUI`, `MainMenuUI`, `SelecTargetUI`, `TwoButtonsCameraGazeControlledCanvas`, `ErrorMessageUI`), handling initial HMD tracking readiness, smooth `CanvasGroup.alpha` fades, a `0.35s` anti-gaze-through input guard on transition, optional smooth soft-follow recentering (`enableSoftFollow`), and positioning in the user's line of sight (`heightOffset = -0.2f`, `standardDistance = 1f`).

### Wheelchair Pose Tracking (`AnchorManager.cs`)
- **Design Context**: Early commits (`0b3c434`, `fc726a8`) experimented with QR Code tracking on the wheelchair armrests (via ZXing/Passthrough Camera and MRUK QR Code tracking). Because Passthrough Camera access is unavailable over Meta Quest Link and MRUK QR tracking was unstable, commit `ab838e0` replaced QR codes with **the two Quest Touch controllers (`LeftAnchor` and `RightAnchor`) mounted in 3D-printed stands on the wheelchair's armrests**.
- In `LateUpdate()`, `AnchorManager` computes `WheelchairRight`, `WheelchairUp`, `WheelchairFoward`, and `WheelchairPosition` (offset by `BackwardsOffset = 0.2f`) directly from `LeftAnchor` and `RightAnchor`.
- All closed-loop control laws read `Wheelchair.transform` from `AnchorManager` as the wheelchair's real-time pose feedback.

### Closed-Loop Control & RestThru HTTP Communication (`RestThruAPI.cs` & `RestThruServer.cs`)
- **`RestThruServer.cs`**:
  - Sends `UnityWebRequest` requests with `Content-Type: application/json` and a 10s timeout.
  - When `payload == null`, sends `"{}"` to avoid empty `UploadHandlerRaw` exceptions in Unity and ensure a valid `Content-Length` header on the server.
  - Endpoints: `Velocity2Endpoint` (`/motion/vel2`), `StopEndpoint` (`/motion/stop`), and `LimitsEndpoint` (`/motion/limits` for periodic server reachability health checks).
- **`RestThruAPI.cs`**:
  - Manages `IDLE`, `BUSY`, and `EMERGENCY_STOP` states. Pressing `X + Y` simultaneously triggers an emergency stop (`ForceStopRobot()`).
  - **`GotoPoint2D`**:
    1. Rotates in place (`±Vrot`) until `|Angle| <= HeadingTolerance` (`5°`).
    2. Tracks the straight line to the target using a PI controller on perpendicular lateral distance (`Kdist`, `Kint`) and a P controller on heading error (`Khead`), halving wheel speeds and gains while quadrupling loop frequency when within `5 * TravelTolerance`.
    3. Stops when within `TravelTolerance` (`0.1m`).
  - **`AlignHeading2D`**:
    - Rotates in place to align `RobotTransform.forward` with `TransformToFollow.forward` (`CenterEyeAnchor`).
    - Uses Bang-Bang control (`±maxVrot`) for errors `> 30°` and PID (`Kp`, `Ki`, `Kd`) for errors `<= 30°`.
    - When within `HeadingTolerance` (`10°`), stops the wheelchair and fills `RotationUI` (`RadialFill`) over `TimeoutToCompletion` (`3s`) of stability to confirm completion.

## 3. Coding & Logging Conventions

- **Language**: All code, comments, commit messages, and documentation must be written in **English**.
- **Logging**: Always use `DebugLogger.Log(...)`, `DebugLogger.LogWarning(...)`, and `DebugLogger.LogError(...)` (`Utils/DebugLogger.cs`), which automatically format log tags as `[PTHFC - ClassName::MethodName]`.
- **Control Telemetry**: Closed-loop controllers in `RestThruAPI.cs` emit `<control_info> { ... } </control_info>` blocks via `DebugLogger.LogWarning`, which are parsed by `Assets/Scenes/PassthroughHandsFreeController/Logs/logs_analyzer.ipynb`. Preserve this JSON structure when modifying control logs.

## 4. MCP Servers & Agent Skills

- **Unity MCP (`unity-mcp`)**: Connects to the running Windows Unity Editor instance via `relay_win.exe --mcp`, exposing `Unity_RunCommand`, `Unity_GetConsoleLogs`, `Unity_SceneView_CaptureMultiAngleSceneView`, and `Unity_AssetGeneration_GenerateAsset`.
- **Meta XR Operator MCP (`metavr`)**: Exposes runtime OpenXR and Unity inspection/input-simulation tools (`openxr_*`, `unity_*`) via `metavr.exe mcp server` when the project is running in Play Mode or on a Quest device.
- **Meta XR Operator Skills (`hz-meta-xr-operator*`)**: Located in `.agents/skills/` for automated runtime testing, coordinate conversion, and XR interaction workflows.
